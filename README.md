# Расширение 1С-Битрикс 20.х сервиса «Экспресс Платежи: Интернет-эквайринг»
 <p>Расширение CMS 1С-Битрикс для интеграции с сервисом «Экспресс Платежи». Расширение позволяет производить прием платежей с помощью банковских карт.</p>

<a href="https://express-pay.by/extensions/1c-bitrix/acquiring">Инструкция для установки и настройки</a>

<a href="https://www.youtube.com/c/express-pay-by">Наш Youtube канал с опубликованными видео по расширениям</a>

Версия: 1.1.2

## Описание

Платёжный обработчик для 1С‑Битрикс (модуль Sale), который создаёт счёт на оплату банковской картой в сервисе «Экспресс Платежи» через API и перенаправляет покупателя на платёжную форму.

Для создания счёта используется метод `web_cardinvoices` API (`https://api.express-pay.by/v1/` либо `https://sandbox-api.express-pay.by/v1/` в тестовом режиме). После оплаты покупатель возвращается на `https://<домен сайта>/bitrix/tools/sale_ps_result.php` с параметром `result=success` или `result=fail`.

Статус оплаты обновляется по входящему уведомлению на `CARD_NOTIFICATION_URL` (по умолчанию `https://<домен сайта>/bitrix/tools/sale_ps_result.php`) с параметрами `Data` и `Signature`.

## Возможности

- Создание счёта на оплату банковской картой через API `web_cardinvoices` и редирект на `FormUrl` из ответа API.
- Поддержка тестового режима (переключение на `sandbox-api.express-pay.by`).
- Формирование цифровой подписи запроса (HMAC-SHA1) по токену и секретному слову.
- Обработка возврата пользователя на страницу магазина: сценарии `result=success` (шаблон `checkout`) и `result=fail` (шаблон `error`).
- Приём уведомлений об изменении статуса оплаты (POST-поля `Data`/`Signature`) и обновление статуса платежа в 1С‑Битрикс.
- Обязательная проверка подписи уведомления (HMAC-SHA1) отдельным секретным словом для уведомлений. Уведомления без подписи или с неверной подписью отклоняются.
- Защита от подделки и повторов: номер счёта (`AccountNo`) и сумма из уведомления сверяются с платежом, уже оплаченный платёж повторно не проводится.
- Поддерживаемые валюты (по ISO 4217): BYN (933), RUB (643), EUR (978), USD (840).

## Требования

- 1С‑Битрикс версии 20.x и выше с модулем «Интернет-магазин» (sale).
- PHP 7.1 и выше.
- Заполненное поле «URL сайта» (`server_name`) в настройках Главного модуля. Из него формируются адрес уведомлений и адреса возврата покупателя. Если в Главном модуле заполнен список доверенных хостов (`trusted_hosts`), `server_name` должен в него входить, иначе счёт не будет выставлен.
- Исходящий доступ с сайта к API:
  - `https://api.express-pay.by/v1/`
  - `https://sandbox-api.express-pay.by/v1/` (для тестового режима).
- Публично доступный по https адрес для уведомлений: `CARD_NOTIFICATION_URL` (по умолчанию `/bitrix/tools/sale_ps_result.php`).
- Данные из личного кабинета «Экспресс Платежи»: API‑ключ (токен), номер услуги (ServiceId), секретное слово для подписи запросов и секретное слово для подписи уведомлений.

## Установка

Обработчик устанавливается вручную, без Маркетплейса. Код тот же, что и в модуле Маркетплейса `triincom.expresspaycard`.

1. Скопируйте папку `install/expresspay_card/` из репозитория на сайт в каталог пользовательских обработчиков платёжных систем, сохранив имя папки `expresspay_card`:
   - `/local/php_interface/include/sale_payment/expresspay_card/` (рекомендуется)
   - или `/bitrix/php_interface/include/sale_payment/expresspay_card/`

   В папке должны оказаться `handler.php`, `.description.php`, `lang/` и `template/`.
2. Файлы обработчика в кодировке UTF-8. Если сайт работает в кодировке windows-1251, перекодируйте файлы из `lang/` и `template/lang/` в windows-1251.
3. Проверьте, что в настройках Главного модуля заполнено поле «URL сайта» (`server_name`) (см. «Требования»).
4. В административной части откройте «Магазин → Настройки → Платёжные системы», добавьте платёжную систему и выберите обработчик «Экспресс Платежи - Интернет-эквайринг» (`expresspay_card`).
5. Заполните параметры обработчика (см. «Настройка») и сохраните.
6. Укажите в личном кабинете «Экспресс Платежи» адрес для уведомлений, равный значению `CARD_NOTIFICATION_URL`, и включите цифровую подпись уведомлений с тем же секретным словом, что и в `CARD_SECRET_WORD_FROM_NOTIFICATION`.

Проверка установки: обработчик появляется в списке доступных обработчиков платёжных систем, а при оформлении заказа становится доступен выбранный способ оплаты.

## Настройка

Параметры задаются в настройках платежной системы в 1С‑Битрикс (значения берутся из `CODES` в `.description.php`):

- **Работа в тестовом режиме** (`CARD_IS_TEST_API`, Y/N) — при включении используется `https://sandbox-api.express-pay.by/v1/`.
- **API‑ключ (токен) доступа к API** (`CARD_TOKEN`) — значение из личного кабинета «Экспресс Платежи».
  - Пример: `YOUR_API_TOKEN`
- **Номер услуги в сервисе «Экспресс Платежи»** (`CARD_SERVICE_ID`) — ServiceId.
  - Пример: `1234`
- **Секретное слово для цифровой подписи** (`CARD_SECRET_WORD`) — используется для подписи запроса создания счёта.
  - Пример: `YOUR_SECRET_WORD`
- **Адрес для получения уведомлений** (`CARD_NOTIFICATION_URL`) — URL обработчика уведомлений. По умолчанию подставляется `https://<server_name>/bitrix/tools/sale_ps_result.php`; если «URL сайта» в Главном модуле не заполнен, поле остаётся пустым и его нужно заполнить вручную. Если сохранённый адрес указывает на другой домен, в настройках выводится предупреждение.
- **Использовать цифровую подпись при получении уведомлений** (`CARD_IS_USE_SIGNATURE_FROM_NOTIFICATION`, Y/N) — по умолчанию `Y`. Подпись уведомлений проверяется всегда, независимо от этой настройки; при значении `N` в настройках выводится предупреждение.
- **Секретное слово для цифровой подписи уведомлений** (`CARD_SECRET_WORD_FROM_NOTIFICATION`) — **обязательно**. Без него уведомления об оплате отклоняются и оплата не засчитывается.
  - Пример: `YOUR_NOTIFICATION_SECRET_WORD`
- **Шаблон назначения платежа** (`CARD_INFO_TEMPLATE`) — строка назначения (до 1024 символов), поддерживает подстановку `##ORDER_ID##`.
  - Пример: `Оплата заказа ##ORDER_ID##`

## Использование

Сценарий оплаты:

1. Покупатель оформляет заказ в 1С‑Битрикс и выбирает оплату через «Экспресс Платежи: Интернет‑эквайринг».
2. Обработчик формирует параметры счёта (`ServiceId`, `AccountNo`, `Amount`, `Currency`, `Info`, `ReturnUrl`, `FailUrl`) и отправляет запрос в API `web_cardinvoices`.
3. При успешном ответе API покупатель перенаправляется на `FormUrl` для ввода данных карты и оплаты.
4. После оплаты покупатель возвращается на `ReturnUrl` (`.../bitrix/tools/sale_ps_result.php?result=success`) либо `FailUrl` (`...?result=fail`), где отображаются соответствующие шаблоны (`checkout`/`error`).
5. Для фиксации оплаты в 1С‑Битрикс сервис отправляет уведомление на `CARD_NOTIFICATION_URL` (POST). Обработчик принимает `Data` (JSON-строка) и `Signature`. При `CmdType = 3` и статусе `3` или `6` он проверяет подпись, номер счёта и сумму и, если всё совпадает, отмечает платёж оплаченным.

Проверка оплаты:

- **Тестовый режим (sandbox)**: включите `CARD_IS_TEST_API = Y`, укажите тестовые значения токена/ServiceId/секретов и выполните оплату через sandbox API.
- **Имитация webhook (проверка обработчика уведомлений)**: отправьте POST на `CARD_NOTIFICATION_URL` с параметрами `Data` и `Signature`.
  - `Data` должна быть JSON‑строкой с полями `CmdType`, `AccountNo`, `Status`, `Amount`, `Payer`.
  - `AccountNo` должен быть ID существующего неоплаченного платежа, а `Amount` — равен сумме этого платежа, иначе уведомление будет отклонено.
  - `Signature` — HMAC‑SHA1 от исходной строки `Data` с ключом `CARD_SECRET_WORD_FROM_NOTIFICATION`, в верхнем регистре (регистр при проверке не учитывается).

Пример `Data` (значения-заглушки):

```json
{"CmdType":3,"Status":3,"AccountNo":100,"Amount":"10.00","Payer":"Иванов И.И."}
```
